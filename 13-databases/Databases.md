# Databases

Databases persist and retrieve application data. Choose a database based on access patterns, consistency, scale, and query needs.

- SQL: structured data, joins, transactions, and strong consistency
- NoSQL: flexible schema and horizontal scale; examples include document, key-value, column, and graph databases
- Index: speeds reads but increases storage and write cost
- Replication: copies data to multiple nodes for availability and read scale
- Sharding: splits data across nodes for write and storage scale
- Transaction: groups operations into one logical unit

Always define the data model, read/write ratio, consistency requirement, and failure behavior before choosing a database.
